**Статус 24.11.2026: план миграции, не развернуто; текущий дневник не менять до проверки нового контура.**

## Промежуточное исправление контроля бесплатного периода (24.11.2026)

- Добавлена Edge Function `diary-access-clock`, возвращающая независимое от часов телефона серверное время и конец тестирования 01.01.2027 00:00 МСК.
- `paid-access.js` измеряет время от ответа сервера через `performance.now()`; при первой загрузке без связи с сервером доступ не разрешается, предусмотрена повторная проверка.
- `index.html` и `accounts.js` не используют `Date.now()` для решения, показывать ли дневник.
- `diary-claim-access` выдаёт `owner_access` только подтверждённой учётной записи владельца по её Supabase Auth UUID. Проверка выполняется на сервере.
- Локальные записи и код экспорта не изменялись. Обновлены query-параметры загрузки JavaScript для обхода кэша.
- Синтаксис трёх обновлённых файлов проверен; 8 изолированных проверок условий дат, прав владельца и блокировки прошли. Реальный браузерный E2E с Supabase/продакшеном не подтверждён из этого окружения.
- **Это временное улучшение интерфейсного ограничения, не защищённый платный продукт.** Рабочий код дневника остаётся публично доступным на GitHub Pages; посетитель с техническими навыками может обойти интерфейс. Новая российская серверная инфраструктура и миграция платного кода по-прежнему необходимы.

## Почему нужен новый сервер

Фактический контур: `accounts.js` регистрирует пользователей через Supabase Auth проекта `cdelycouqiparwsqwtxw`, регион `eu-west-1`. В нём создаются учетные записи (email, пароль в виде хеша, информация о подтверждении). Оплаченные заказы также настроены в зарубежной БД `public.diary_paid_orders`. По части 5 ст. 18 закона №152-ФЗ с 01.07.2025, если применимы требования к сбору персональных данных граждан РФ, такая схема требует пересмотра. Функциональность дневника и локальные записи отдельно от этого вопроса.

Коммерческое размещение на GitHub Pages также не соответствует предназначению сервиса согласно GitHub Pages limits: нужно перенести публичную версию на разрешенный хостинг.

## Минимальный целевой контур

1. Российский веб-хостинг с PHP 8.2+ (или эквивалент), MySQL/MariaDB и HTTPS; **база данных, резервные копии и операции обработки — на территории РФ**, подтвердить в договоре и панели управления. Проверить условия поручения обработки данных и техническую защиту.
2. Один публичный сайт `https://<выбранный_адрес>/`: прежний HTML/JS/CSS и ресурсы **без изменения функций дневника**, плюс серверный API на том же домене. Так не требуется CORS к зарубежному API.
3. Серверный API должен поддерживать: регистрацию и подтверждение email, вход/выход, восстановление пароля, токены с истечением срока и защитой, проверку оплаченного периода, отзыв/возврат покупки. Нельзя переносить секреты в JavaScript; пароли — Argon2id/bcrypt, не хранить в открытом виде. Rate limiting, безопасные cookie, CSRF/Origin для изменяющих запросов и настройки резервного копирования обязательны.
4. Отдельный `/api/prodamus-webhook`: подпись HMAC, точные названия тарифов, суммы, дедлайн предпродажи МСК, деморежим никогда не дает доступа, idempotent order ID, отмены/возвраты отзывают доступ; письма и статусы покупателя не считать доказательством платежа.
5. Не отдавать платный рабочий код публичным URL в период платного доступа: переносится за серверное разрешение. Локальные записи остаются в браузере и не уходят на сервер.
6. Отправка писем для подтверждения email должна поддерживаться российской почтовой инфраструктурой на выбранном хостинге; в 10-дневный пробный период Timeweb создание ящиков недоступно.
7. Публикация/регистрация: актуальная политика ПД, основания и согласия, правила cookie/Метрики, информация об исполнителе, оферта с периодами/содержанием услуги, порядок возвратов, чек НПД; перед запуском нужна юридическая проверка документов и схемы передач.
8. Не смешивать технические секреты с репозиторием; только переменные конфигурации вне webroot/на сервере; не переносить реальные персональные данные пользователей в тестовую БД.

## Два существующих аккаунта и локальные записи

- В зарубежном Supabase на момент проверки **2 подтвержденных аккаунта**, 0 реальных платных заказов.
- Нельзя считать, что пароли Supabase автоматически перенесутся: новый сервер использует отдельные учетные записи. Предусмотреть подтверждение новой регистрации/сброс пароля.
- `accounts.js` привязывает локальное хранилище к ID учетной записи. При смене домена localStorage **не переносится автоматически**. До миграции каждый тестировщик должен скачать резервную копию JSON через интерфейс дневника; в новой версии — восстановить JSON после входа в нужный аккаунт, проверив что записи на месте. Не очищать старый сайт/хранилище, пока восстановление не подтверждено. Проверить отдельно зашифрованные записи и восстановление локальной защиты.
- Две существующие записи аккаунтов не удалять без подтвержденного плана миграции и оснований.

## Кандидаты на российское размещение, без обязательств

- Beget FreeHosting: 0 ₽, PHP/MySQL, но **запрещена отправка почты любым способом**; при нагрузке возможно отключение PHP-сессий. Для текущего сценария с email-аккаунтами не рекомендовать как готовую рабочую платформу.
- Timeweb обычный PHP-хостинг: тест 10 дней без привязки карты; платный тариф зависит от периода оплаты и акции, уточнить сумму **к списанию за один месяц** до принятия решения. На пробном периоде почта недоступна. Выбирать сервер/БД РФ и проверить договорные условия ПД.
- Не покупать VPS, отдельную БД, платный домен или подписки до сравнения итоговой стоимости и теста.
